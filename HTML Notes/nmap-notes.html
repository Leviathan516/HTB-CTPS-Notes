Introduction — TCP-SYN Scan

The TCP-SYN scan (-sS) is the default scan method and one of the most popular. It can scan several thousand ports per second. A SYN packet is sent but the three-way handshake is never completed — no full TCP connection is established.

How SYN Scan Determines Port State

💡 Why SYN scan is stealthy
Because the handshake never completes, many older logging systems and services won't record the connection — making it less detectable than a full Connect scan (-sT).
02
Host Discovery
Ping Scan — -sn

Disables port scanning. Nmap automatically sends ICMP Echo Requests (-PE) to discover live hosts. On local networks, it first sends an ARP ping — ARP replies confirm a host is alive before any ICMP is sent.

Ping scan with packet trace
$ sudo nmap 10.129.2.18 -sn -oA host -PE --packet-trace SENT (0.0074s) ARP who-has 10.129.2.18 tell 10.10.14.2 RCVD (0.0309s) ARP reply 10.129.2.18 is-at DE:AD:00:00:BE:EF Host is up (0.023s latency). MAC Address: DE:AD:00:00:BE:EF
--packet-trace

Shows every packet sent and received. Essential for understanding why Nmap produced a result — especially useful when diagnosing filtered ports or unexpected host states.

--reason

Displays the specific reason Nmap marked a host or port with its state (e.g. arp-response, syn-ack, no-response). Great for building intuition.

FlagDescription
-snDisable port scanning — host discovery only
-PEUse ICMP Echo Requests for ping
-PnSkip host discovery — treat all hosts as online (useful if ICMP is blocked)
--disable-arp-pingSuppress ARP pings on local networks
-nDisable DNS resolution — speeds up scans
--packet-traceShow all packets sent and received
--reasonShow reason for each port/host state
03
Host & Port Scanning
The 6 Port States
StateDescription
open Connection established — TCP, UDP, or SCTP. These are your targets.
closed Received an RST flag back. Port is accessible but no service is listening.
filtered No response, or an error code returned. Firewall likely dropping/rejecting packets.
unfiltered Only from ACK scan (-sA). Port accessible but open/closed can't be determined.
open|filtered No response — firewall or filter may be protecting the port.
closed|filtered Only from IP ID idle scans. Impossible to determine if closed or filtered.
Scan Types
SYN Scan DEFAULT
-sS

Sends SYN, never completes handshake. Thousands of ports/second. Requires root. Less likely to appear in logs.

Connect Scan
-sT

Full three-way handshake. Slower, but works without root. Leaves full connection logs.

ACK Scan EVASION
-sA

Sends only ACK flag. Harder to filter — firewalls often pass ACK packets since they can't tell if the connection originated internally. Returns unfiltered state.

UDP Scan
-sU

Scans UDP ports. Much slower than TCP. Critical for SNMP (161), DNS (53), DHCP, and other UDP services.

Port Selection
FlagDescription
-p-Scan all 65,535 ports
-p22-110Scan a range of ports
-p22,25,80Scan specific ports only
-FFast scan — top 100 ports only
--top-ports=<num>Scan the N most common ports
Output Formats
# Save in all formats at once (recommended) $ nmap ... -oA scan_output # creates .nmap .xml .gnmap # Individual formats $ nmap ... -oN scan.txt # normal (human-readable) $ nmap ... -oX scan.xml # XML (parse with tools) $ nmap ... -oG scan.gnmap # grepable # Convert XML to HTML report $ xsltproc target.xml -o target.html
💡 Always save output
Use -oA on every scan. Re-running a scan later wastes time, may alert IDS, and results can differ. The XML output is also parseable by tools like Metasploit.
04
Service Enumeration
Version Detection KEY
-sV

Probes open ports to determine the service name and version. Banner grabbing + service fingerprinting. Version strings are essential for matching known CVEs.

OS Detection
-O

Attempts to determine the target's operating system via TCP/IP stack fingerprinting. Requires root and at least one open + one closed port.

Aggressive Scan
-A

Combines OS detection, version detection, script scanning, and traceroute in one flag. Noisy but comprehensive.

Default Scripts
-sC

Runs the NSE scripts categorised as default. Safe for most targets. Commonly paired with -sV.

Standard enumeration combo
$ sudo nmap 10.129.2.28 -sV -sC -O -oA full_scan # Add -p- for all ports, or --top-ports=1000 for the top 1000

Nmap Scripting Engine (NSE)

NSE scripts extend Nmap's capabilities far beyond port scanning. Scripts are organized into categories. Run with --script <name-or-category>.

CategoryDescriptionUse When
defaultRun automatically with -sCEvery scan — safe, informative
authCredential determinationTesting for default/no-auth access
bruteBrute-force loginsWhen you have a wordlist and a service login
discoveryEvaluate accessible servicesExpanding knowledge of the target
vulnIdentify specific vulnerabilitiesAfter service versions are known
exploitAttempt to exploit known vulnsControlled, consented tests only
safeNon-intrusive, defensive scriptsWhen impact must be minimised
versionExtend service detectionComplement to -sV
broadcastHost discovery via broadcastLAN enumeration
intrusiveMay negatively affect the targetOnly in fully authorised tests
malwareCheck for malware infectionIncident response scenarios
dosTest for DoS vulnerabilitiesRarely — harms the service
fuzzerUnexpected input handling testsLong-running, targeted fuzzing
externalUses external servicesOSINT enrichment
Script Usage Examples
# Run default scripts $ nmap 10.129.2.28 -sC # Run a specific script $ nmap 10.129.2.28 --script smtp-commands # Run a category $ nmap 10.129.2.28 --script vuln # Run multiple scripts $ nmap 10.129.2.28 --script ms-sql-info,ms-sql-ntlm-info # Wildcard — all scripts matching a pattern $ nmap 10.129.2.28 --script "nfs*" # Search for available scripts $ find / -name "*.nse" | xargs grep -l "smb" 2>/dev/null

Performance Tuning
Timing Templates -T <0–5>
T0
paranoid
T1
sneaky
T2
polite
T3
normal ✓
T4
aggressive
T5
insane

T3 is the default. T4/T5 sacrifice accuracy for speed — may miss hosts on high-latency links. T0/T1 are for IDS evasion (very slow).

RTT Timeout Tuning

Nmap's default initial RTT is 100ms. Reducing it speeds up scans but risks missing slow hosts.

# Default — 39 seconds for /24 $ sudo nmap 10.129.2.0/24 -F # Optimised RTT — ~12 seconds (but missed 2 hosts) $ sudo nmap 10.129.2.0/24 -F --initial-rtt-timeout 50ms --max-rtt-timeout 100ms
⚠ Accuracy vs Speed
Setting --initial-rtt-timeout too low can cause you to miss hosts entirely. In the example above, 2 hosts were lost. Use aggressive RTT only when speed matters more than completeness.
Packet Rate

When you know the network bandwidth (e.g. a white-box test where you're whitelisted), set --min-rate to blast packets as fast as possible.

# Default — 29 seconds $ sudo nmap 10.129.2.0/24 -F # 300 packets/sec — ~8 seconds (same host count) $ sudo nmap 10.129.2.0/24 -F --min-rate 300
Max Retries

Default is 10 retries per port. Reduce to 0 to skip any port that doesn't respond on the first packet — big speed gain, some accuracy loss.

$ sudo nmap 10.129.2.0/24 -F --max-retries 0

Firewall & IDS/IPS Evasion
Dropped Packets

Firewall silently discards the packet. No response returned. Nmap marks the port filtered.

Rejected Packets

Firewall sends an explicit response back — TCP RST or an ICMP error code (Net Unreachable, Host Prohibited, Port Unreachable, etc.).

ACK Scan for Firewall Mapping KEY TECHNIQUE
-sA

Sends only the ACK flag. Firewalls generally pass ACK packets because they can't determine whether the connection originated internally or externally — unlike SYN packets, which external firewalls almost always block. Use to discover which ports are unfiltered vs filtered.

Decoys & Source Spoofing
Decoy Scan NOISY
# Mix your real IP with 5 random decoys $ sudo nmap 10.129.2.28 -D RND:5 # Specify exact decoy IPs $ sudo nmap 10.129.2.28 -D 10.10.1.1,10.10.1.2,ME

Makes it harder for defenders to identify the real source among multiple apparent scanners.

Source IP & Interface Spoofing
# Specify source IP address $ sudo nmap 10.129.2.28 -S 10.10.10.200 -e eth0 # Specify source port (e.g. appear to come from port 53 — DNS) $ sudo nmap 10.129.2.28 -g 53 # Use a specific DNS server for resolution $ sudo nmap 10.129.2.28 --dns-server <ns>
💡 Evasion Strategy Summary
Use -sA to map what's actually reachable through the firewall. Use decoys (-D) to obscure your real IP. Use -g 53 to make traffic look like DNS. Use -Pn when ICMP is blocked and you already know the host is up.
